為什麼是 Arduino C++，不是 MicroPython

Cardputer ADV 官方支援四種開發方式：Arduino、PlatformIO、ESP-IDF、UIFlow2（圖形化）。 以你的目標——電子琴要吃 I2S 音訊、額度記錄器要連網、相機要處理影像——建議直接鎖定 Arduino 框架 + M5Cardputer 函式庫，理由很實際：

  • 硬體驅動都在這裡。ES8311 音訊編解碼器、TCA8418 鍵盤控制器、BMI270 六軸、ST7789V2 螢幕，官方 M5Unified 全部包好了。MicroPython / UIFlow2 對 ADV 的新硬體支援一定落後。
  • 社群範例幾乎全是 C++。你之後想抄的 Cardputer 專案（遊戲、駭客工具、時鐘）九成用 Arduino 寫。
  • ESP32 沒有 PSRAM 的餘裕給直譯器。ADV 只有 512KB SRAM，Python 直譯器加 WiFi 協定堆疊會很快撞牆。
  • PlatformIO 的體驗跟你熟的一模一樣。platformio.ini 就是 package.json，lib_deps 就是 dependencies，一行指令編譯燒錄。

但你的 Node.js 完全不會浪費——反而是關鍵。這份路線圖的架構一直是 裝置只負責顯示與輸入，資料與邏輯留在你 Mac 上的 Node 服務。 第 06 課的 Claude 額度記錄器就是這個模式的示範。

00

認識手上這台機器，先買好救磚保險

在寫任何一行程式之前，先確定你「隨時可以回到出廠狀態」。這件事做完，後面所有實驗你都不會害怕。

  • 裝 M5Burner。M5Stack 官方燒錄工具，裡面可以直接下載並燒回 Launcher 或原廠韌體。之後不管你把機器搞成什麼樣，插上 USB-C 燒一次就回來了。
  • 練熟下載模式。側邊電源開關撥到 OFF → 按住機身上的 G0 按鈕 → 插上 USB-C → 放開。這是每次燒錄卡住時的萬用解法。
  • 準備一張 microSD。格式化成 FAT32（不是 exFAT）。Launcher 和之後的資料存檔都靠它。
  • 認識它沒有什麼。沒有觸控、沒有 PSRAM、沒有獨立 RTC 晶片、沒有相機。這三個「沒有」會影響你後面的設計決策。
產出你能在 30 秒內把機器燒回 Launcher，並且知道下載模式怎麼進。

開發環境：先用 Arduino IDE 拿到成就感

我建議第一天先用 Arduino IDE 2.x，因為 M5 官方文件全部以它為準，出問題比較好查。 等你跑通 Hello World、確認硬體沒問題之後，第 04 課再搬到 PlatformIO。

02

顯示：M5GFX 與 Sprite 雙緩衝

直接往 Display 上畫，畫面會閃。正確做法是畫在記憶體裡的 Sprite（離螢幕畫布），一次推上去——概念就是 canvas 的雙緩衝，或你熟的 virtual DOM 一次 patch。

  • 中文顯示：內建字型只有 ASCII。要顯示中文，用 M5GFX 的 efont 字型（canvas.setFont(&fonts::efontCN_16)），或把需要的字做成點陣圖。全字庫很吃 flash，先想清楚要不要中文。
  • 畫面很小：240×135 大約只放得下 6 行 16px 文字。設計時就以「一次只顯示一件事」為前提。
  • 背光：M5Cardputer.Display.setBrightness(0~255)，做電子雞這種長時間開著的 app 要記得調暗省電。
產出一個不閃爍、跑 30fps 的動畫畫面，以及一個你能重複使用的 render() 函式。
03

鍵盤：讀鍵、做一個輸入框

ADV 用的是 TCA8418 鍵盤控制器（走 I2C，有中斷腳），但 M5Cardputer 函式庫把它包成跟初代一樣的 API， 你不用管底層差異。核心只有三個呼叫。

  • isChange() 是「這一輪跟上一輪不同」——等同 watch()，用它來避免每圈都重畫。
  • keysState() 回傳的結構裡有 word（字元陣列）、enter、del、tab、fn、ctrl、shift、opt、alt。
  • 要做遊戲的話別用這個——用 isKeyPressed('z') 檢查「當下是否按住」，才有連續移動的手感。
產出可以打字、退格、按 Enter 送出的輸入框。這會是第 06 課填 WiFi 密碼的元件。
04

主迴圈與狀態機：丟掉 delay()，搬到 PlatformIO

這一課沒有新硬體，但它決定你之後的程式好不好維護。delay() 會凍結整台機器—— 按鍵讀不到、WiFi 不回應、聲音會斷。它相當於在 Node 主執行緒裡跑 while 空轉。

再加上一個 enum AppState { MENU, RUNNING, PAUSED } 的狀態機，你的 app 骨架就完成了。 之後每個專案都是同一個骨架換內容。

指令對照

pio run 編譯 · pio run -t upload 燒錄 · pio device monitor 看 log。 這三個指令就是你的 npm run build / deploy / logs，也是第 11 課讓 Claude Code 自己跑的入口。

如果編譯失敗

PlatformIO 官方的 espressif32 平台版本比 M5 官方板管落後，有時對不上新版函式庫。遇到怪錯誤時， 把 platform 換成社群維護的 pioarduino 平台（提供較新的 ESP32 Arduino 核心）， 或先退回 Arduino IDE 確認不是程式本身的問題。

05

聲音 → 電子琴

ADV 的音訊路徑是 ES8311 編解碼器 + NS4150B 放大器 + 1W 喇叭，而且多了 3.5mm 耳機孔 （插入耳機時喇叭會自動靜音）。M5Unified 的 Speaker 已經把這條路徑包好， 最重要的是它支援 最多 8 個虛擬聲道——這就是你的複音。

  • 先做到會響，再做好聽。tone() 是方波，聽起來像紅白機。想要更像琴，下一步是用 playRaw() 餵自己算的波形陣列，加上 ADSR 包絡。
  • 加畫面回饋。把第 02 課的 Sprite 拿來畫琴鍵，按下去的鍵反白——這樣它才像一台樂器而不是一個實驗。
  • 錄音也在這裡。ADV 有 MEMS 麥克風（SNR 65dB），M5Cardputer.Mic 可以錄下來存到 SD 卡。取樣器是很自然的下一個版本。
產出按鍵會發出正確音高、可以按和弦、能升降八度、螢幕上有琴鍵回饋的電子琴。
06

連網 → Claude 額度記錄器

這一課是你最有優勢的地方。架構上請不要讓 Cardputer 直接打 Anthropic 的 API， 原因很具體：ESP32 要跑 TLS + 憑證驗證、沒有 PSRAM、而且你不會想把金鑰燒進韌體裡。 正確的分工是——你的 Mac 上跑一個 Node 小服務，Cardputer 只在區網內抓一包乾淨的 JSON。

先確認你要記錄的是哪一種額度

Claude Code 訂閱制（Pro / Max）：沒有公開的用量查詢 API。資料在你本機 ~/.claude/ 底下， 用 Node 讀出來就好——這反而比呼叫 API 更即時。

Console API key 計費：有 Admin API 的用量與成本報表 （GET /v1/organizations/usage_report/messages、/v1/organizations/cost_report）， 需要 Console 建立的 Admin API key（sk-ant-admin…），而且這兩個端點目前只能用原始 HTTP 呼叫、SDK 沒有包。

  • 顯示要能一眼看懂。240×135 放不下表格。建議：一個大數字（今日花費）+ 一條橫向長條（佔每日預算的比例）+ 右下角更新時間。
  • 用顏色編碼狀態，別只靠數字：綠 → 黃 → 橘，越接近你設的上限越紅。
  • 下一步：把 bridge 換成 SSE 或 WebSocket 推播、加上七天趨勢的小折線圖、快到上限時用喇叭嗶一聲。
產出放在桌上的實體儀表板，隨時看得到今天燒了多少額度。
07

存檔與時間 → 電子雞

電子雞的技術核心其實只有一句話：關機期間也要繼續變老。 所以你需要「持久化的狀態」加上「可信的時間差」。

  • 存檔用 NVS（Preferences），不要用 SD 卡。它寫在 flash 裡，斷電不掉，API 幾乎就是 localStorage。SD 卡留給圖片、音效、log。
  • 時間要靠 NTP。ADV 沒有獨立的 RTC 晶片，斷電後時間會歸零。做法是開機連上 WiFi 後對一次時，把 epoch 存進 NVS。
  • 離線衰減：開機時算 now - lastSeen，一次補完這段時間該掉的飢餓值與心情值。
寫入次數要克制

Flash 有抹寫壽命。不要每一圈都存檔——每 5 分鐘、或狀態真的改變時再寫。這也是為什麼第 04 課的排程器要先做好。

剩下的就全是設計了：像素角色動畫（把每一幀畫進 Sprite）、餵食／玩耍／清理三個動作綁按鍵、 肚子餓時用喇叭叫、搖晃機器（第 08 課的 IMU）逗牠玩。

產出一隻關機隔天再開會餓的電子寵物。

10

外接相機：Unit CamS3

先修正一個常見誤解

Cardputer ADV 沒有辦法直接驅動裸相機模組——Grove 埠只有兩根訊號線，而且機器沒有 PSRAM， 連一張 VGA 的影格都放不下。所以 M5 的相機配件（Unit CamS3 / CamS3-5MP）本身就是一台完整的 ESP32-S3 電腦， 帶 8MB PSRAM、16MB flash、自己的 microSD 和 WiFi。

正確的心智模型是：相機是一台伺服器，Cardputer 是它的遙控器與觀景窗。 對你來說再熟悉不過——這就是前後端分離，只是後端變成一顆會拍照的東西。

  • CamS3 端：可以用原廠韌體（拍照 + 上傳雲端），或自己燒一份簡單的 HTTP server，開出 /capture、/stream、/thumb?w=240 三個端點。
  • Cardputer 端：抓 /thumb 回來的小張 JPEG，用 M5GFX 的 drawJpg() 直接畫上螢幕。務必讓相機那端先縮圖——不要把 2592×1944 的原圖丟給 Cardputer 解。
  • 加值的地方在 Cardputer：有鍵盤，所以可以現場替照片下標題、選拍攝參數、瀏覽 SD 卡裡的相簿。這是純相機做不到的。

這個專案值得晚一點做，但它會把前面全部串起來：WiFi（06）、JSON（06）、鍵盤（03）、Sprite（02）、SD 卡（07）。

產出一台可以遙控快門、現場加標題、翻看縮圖的口袋相機組。
11

讓 Claude Code 幫你寫韌體

你已經在用 Claude Code。把韌體專案設定好之後，它可以自己編譯、自己燒錄、自己讀序列埠的錯誤訊息再修—— 這對嵌入式開發特別有價值，因為「編譯 → 燒 → 看 log」這個迴圈很煩，但很機械。

  • 把硬體限制寫進 CLAUDE.md，尤其「沒有 PSRAM」和「禁用 delay()」——這兩件事模型不知道就會寫出跑不動的程式。
  • 讓它自己看 log。esp32_exception_decoder 開著的話，當機的 backtrace 會直接翻成檔名行號，Claude 讀得懂。
  • Node 那半邊更是它的主場——bridge、OTA server、相機端的 API，直接交給它。
產出一個你只要說「加一個電量顯示在右上角」就會自己編譯燒錄驗證的專案。

setTextSize(2)字型倍率不是像素。基準 8px，所以 2 = 16px 高
drawString(s, 10, 56)10, 56 是左上角座標。垂直置中 ≈ (135 − 16) / 2
Serial.begin(115200)傳輸速率，必須跟 make monitor 一致，不然是亂碼
M5Cardputer.update()輪詢硬體狀態存進物件裡。沒有中斷、沒有事件監聽器，你要主動去問。漏掉這行鍵盤就是死的

兩個觀念

畫上去就留著。 螢幕自己有記憶，setup() 結束後字不會消失。跟瀏覽器每幀重繪的模型完全不同 —— 只在需要改變時才畫。

M5 和 M5Cardputer 是兩個物件，不是筆誤。 M5 來自底層 M5Unified，M5Cardputer 包在外面、多了鍵盤。

實測數字

每次編譯瞄一眼第二個數字，突然掉很多就是有東西吃記憶體。

踩過的坑

  • 序列埠看不到 booted —— 它只在開機那一瞬間印一次。正確順序是先開監控、再讓機器重開：make monitor 開著，然後電源 OFF → ON。嵌入式沒有捲軸歷史，你不在場就是沒看到。
  • 不用手動進下載模式 —— ESP32-S3 的原生 USB 可以自己重置。真的卡住時才需要：電源 OFF → 按住 G0 → 插 USB-C → 放開。

實作紀錄 · SpriteDemo/

按任意鍵切換兩種畫法，親眼看差別。

燒錄

開機是紅字 DIRECT（故意的錯誤示範）—— 橘球會閃爍。 按任一鍵變綠字 SPRITE —— 同一顆球變滑順。

差別只在一件事

M5Canvas 就是一塊 240×135 的記憶體。所有繪圖在那裡完成，pushSprite() 才把成品整批送出。 概念同 virtual DOM：先在記憶體算出最終樣子，再一次性套用。

三個發現

fps 兩種模式差不多。 瓶頸不在畫圖而在 SPI 傳輸 —— Sprite 解決的是視覺撕裂，不是速度。

狀態與畫面要分離。 step() 只更新資料、drawXxx() 只負責畫。 之後每個專案都用這個骨架。

記憶體代價比想像小。 全域只比第 01 課多 384 bytes（301732 → 301348）， 因為 Sprite 的 32KB 是在 setup() 裡動態配置的，不算全域。 開機時序列埠會印出真實剩餘量。

可以動手改

改哪裡會發生什麼
setColorDepth(8) → 16顏色變準，記憶體 32KB → 63KB
now - lastFrame < 16 → 100降到 10fps，DIRECT 的閃爍更明顯
fillCircle → fillRect(x, y, w, h, c)球變方塊
